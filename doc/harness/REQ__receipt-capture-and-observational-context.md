# Native receipt capture and observational task context

Reading task_context must not acquire or change task ownership, active focus, watcher registration, or conflict fences. Reading another coordinator's open task is safe. Use task_start with the existing task id and without fresh_run to explicitly resume and bind the unchanged run. Two explicitly started distinct open tasks in one coordinator remain ambiguous and must still be fenced. Independent coordinators can work on different tasks without sharing ownership. This applies to bare and qualified tool calls, an exact process-owned session id, and registered worktree reads. Existing exact/default/legacy markers and registration remain unchanged on reads, even under a conflict fence. Closed tasks stay closed; coordinator cleanup reads never resume them.

The watcher must persist authenticated start/completion pairs for valid native children even when child log publication and parent delivery are asynchronous. Transient incomplete evidence must be retried rather than permanently discarding an otherwise valid child. Permanent contradictory identities, ambiguous final deliveries, wrong task/run, and untrusted files remain non-attesting. Tests must reproduce a loss before correction and show actual receipt storage afterward; successfully parsing an already complete child file alone is insufficient.

Deployments must preserve existing user task state and receipt files. Synthetic reproduction belongs in disposable test repositories. Historical records must not be reconstructed or marked PASS as part of a fix. Already running Python processes require fresh startup to use changed loaded modules unless a supported safe reload is explicitly verified.

Reproduction confirmed that three transient observation exceptions on a valid native spawn exhaust the worker's local retries, discard the spawn, and return success without either receipt. This proves a loss mechanism, not the exact historical trigger in the project logs. Exhausting bounded retries must instead return a failed worker result so the manager replays its unchanged registration checkpoint. Recovery must read that checkpoint even when the rollout's modification time is older than the idle window. A first worker with registered unread backlog must also consume it before applying the idle timeout; idle age alone is not evidence that the checkpoint was processed. Exact existing receipts remain idempotent; malformed non-evidence lines and contradictory identities retain their existing rejection rules. Unresolved observation errors at idle expiry must not be reported as successful consumption.

Idle expiry with a correlated, non-rejected child still awaiting transcript evidence must also remain retryable, even when no exception occurred. A delivered parent final is not enough to attest completion, but its pending child evidence must survive a worker's idle window through checkpoint replay. Explicit manager shutdown still stops promptly. Integration must delay the actual child transcript until after one worker expires, then prove automatic storage and duplicate-free replay.

Idle expiry applies while waiting for input, never between unread complete records merely because processing the previous record consumed time. A worker may retire successfully only after consuming its available backlog; slow receipt storage must not turn remaining parent evidence into unobserved history.
